# Adapter

## 목표

서로 다른 인터페이스를 가진 기존 기능을 필요한 방식으로 연결합니다.

## 만들어 볼 기능

아래 예시 중 하나를 선택하거나 같은 목표를 연습할 수 있는 기능을 직접 정합니다.

1. **환율 조회**: 외부 서비스의 통화 코드와 환율 응답을 앱이 사용하는 환율 조회 형식으로 바꿔 가격을 계산합니다.
2. **결제 연동**: 결제 서비스마다 다른 결제 요청과 응답을 앱의 공통 결제 인터페이스로 연결해 성공 또는 실패를 확인합니다.
3. **가계부 거래 가져오기**: 은행마다 날짜·거래처·금액의 열 순서가 다른 CSV를 읽고, 가계부에서 사용하는 공통 거래 형식으로 변환해 목록에 표시합니다. 같은 디렉터리의 `bank-a.csv`와 `bank-b.csv`를 사용할 수 있습니다.

## 실습 조건

호출하는 쪽의 인터페이스와 기존 기능의 인터페이스를 다르게 정의하고, 둘을 연결하는 어댑터를 구현하세요. 외부 서비스 대신 테스트용 객체를 사용해도 됩니다.

## 생각해 볼 질문

변환 책임을 호출자에 두는 것과 어댑터에 두는 것의 차이는 무엇인가요? 변환 과정에서 표현할 수 없는 정보는 어떻게 다룰까요?

## 완료 기준

선택한 기능의 동작을 테스트 또는 실행 결과로 확인하고, 패턴을 적용한 이유와 더 단순한 대안의 장단점을 자신의 말로 정리합니다.
