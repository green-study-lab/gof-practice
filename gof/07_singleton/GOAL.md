# Singleton

## 목표

공유 인스턴스가 하나만 필요하다는 제약을 표현하고 그 영향을 살펴봅니다.

## 만들어 볼 기능

아래 예시 중 하나를 선택하거나 같은 목표를 연습할 수 있는 기능을 직접 정합니다.

1. **애플리케이션 설정**: 설정 저장소에서 언어를 변경하고, 다른 기능에서 같은 저장소를 조회해 변경된 설정을 확인합니다.
2. **공유 작업 대기열**: 여러 기능이 하나의 대기열에 작업을 추가하고, 실행기가 이를 순서대로 꺼냅니다. 직접 생성 제한과 외부 주입 방식을 비교합니다.

## 실습 조건

여러 곳에서 같은 인스턴스를 얻는지 확인하고, 상태가 있다면 테스트 간에 영향이 생기는지도 살펴보세요.

이 예시는 Singleton의 사용법과 한계를 비교하기 위한 실습입니다. 공유 객체가 필요하다는 사실만으로 Singleton이 반드시 필요한 것은 아닙니다.

## 생각해 볼 질문

전역 상태는 테스트와 동시성에 어떤 영향을 줄까요? 인스턴스를 외부에서 하나만 만들어 전달하는 방식과 어떻게 다른가요?

## 완료 기준

선택한 기능의 동작을 테스트 또는 실행 결과로 확인하고, 패턴을 적용한 이유와 더 단순한 대안의 장단점을 자신의 말로 정리합니다.
