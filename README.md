# GoF Practice

GoF 디자인 패턴을 소재로 작은 기능을 만들고, 설계 선택과 사용하는 언어의 기능을 직접 실험하는 공용 스터디 저장소입니다.

## 스터디 목표

- 각 패턴이 해결하려는 문제와 적용하기 적절한 상황을 이해합니다.
- 알림, 문서, 게임 등 다양한 기능에 패턴을 적용하고 결과를 확인합니다.
- 패턴을 적용한 구현과 더 단순한 대안을 비교하고, 얻는 이점과 복잡도를 설명합니다.
- 각자 선택한 언어의 문법과 기능을 사용하고, 궁금한 동작을 테스트나 실험으로 확인합니다.
- AI를 활용할 경우 제안받은 구현을 실행하고 검증하며, 여러 설계의 차이를 살펴봅니다.

23개 패턴을 빠짐없이 구현하는 것 자체보다, 필요한 문제에 어떤 선택이 적합한지 이해하는 데 집중합니다.

## 왜 GoF를 공부하나요?

AI가 코드를 빠르게 만들어 주더라도 어떤 동작이 달라지고 어떤 제약을 지켜야 하는지, 여러 구현 중 무엇을 선택할지는 여전히 살펴볼 가치가 있습니다. GoF는 반복되는 설계 문제와 그 해결 방식을 비교하고 이야기할 수 있는 출발점입니다. 예를 들어 Strategy를 연습하면서 바뀌는 규칙을 분리할 때의 이점과 단순한 조건문으로 충분할 때를 함께 생각할 수 있습니다.

패턴 이름이나 클래스 구조를 외우는 것이 목표는 아닙니다. 현대 언어에서는 함수, 표준 라이브러리, 프레임워크가 같은 의도를 더 간결하게 표현하기도 합니다. 그래서 이 스터디에서는 패턴을 적용하지 않는 선택도 정답이 될 수 있습니다.

이 관점의 근거와 한계는 [최근 자료를 바탕으로 정리한 학습 이유](docs/why-study-gof.md)에서 확인할 수 있습니다.

## 저장소 구성

`gof/`에는 언어에 독립적인 23개 패턴의 실습 목표가 있습니다. 각 `GOAL.md`에는 선택할 수 있는 기능 예시, 실습 조건, 생각해 볼 질문이 담겨 있습니다.

외부 서비스나 실제 기기 없이 가짜 데이터로 실습해도 됩니다.

```text
gof-practice/
├── README.md
├── docs/why-study-gof.md       # 학습 이유와 최근 자료
└── gof/
    ├── 01_strategy/GOAL.md
    ├── 02_template-method/GOAL.md
    ├── 03_factory-method/GOAL.md
    └── ...                      # 나머지 GoF 패턴의 목표
```

## 권장 학습 순서

디렉터리 번호는 앞에서 익힌 개념을 다음 패턴에 연결하기 위한 권장 순서입니다. 반드시 선행해야 하는 규칙은 아니므로 관심 있는 패턴부터 시작해도 됩니다.

1. **01~07 — 동작과 객체 생성:** Strategy와 Template Method로 다형성과 상속을 살펴본 뒤, Factory Method와 Abstract Factory를 비교합니다. Builder, Prototype, Singleton으로 객체를 만들고 관리하는 다른 방법도 연습합니다.
2. **08~14 — 객체의 조합:** Adapter와 Bridge로 서로 다른 구성 요소를 연결하고, Decorator·Composite·Facade·Proxy·Flyweight로 객체를 감싸거나 묶고 공유하는 방식을 살펴봅니다.
3. **15~20 — 요청과 협력:** Chain of Responsibility와 Command로 요청을 다루고, Memento·Iterator·Observer·Mediator로 상태 저장과 객체 간 협력을 연습합니다.
4. **21~23 — 상태와 구조에 따른 동작:** State, Interpreter, Visitor를 통해 상태나 객체 구조에 따라 동작을 나누는 방식을 살펴봅니다.

특히 Factory Method를 보고 Abstract Factory를 비교하거나, Decorator를 보고 Proxy를 비교하고, Observer를 보고 Mediator를 살펴보면 각 패턴의 의도 차이를 이해하기 쉽습니다. Composite를 익힌 뒤에는 Interpreter의 표현식 구조와 Visitor가 다루는 객체 구조를 살펴볼 수 있습니다.

## 참여 방법

1. 이 저장소를 자신의 GitHub 계정으로 fork하고 로컬에 내려받습니다.
2. `gof/`에서 연습할 패턴을 고르고 `GOAL.md`를 읽습니다.
3. 예시 기능 중 하나를 선택하거나 같은 목표에 맞는 기능을 직접 정합니다.
4. 자신의 fork에서 `gof/` 옆에 원하는 언어 디렉터리를 만들고, 그 안에 실습 프로젝트와 코드를 자유롭게 구성합니다.
5. 실행이나 테스트로 결과를 확인하고, 설계 이유와 학습 내용을 기록합니다.

예를 들어 Java와 Kotlin을 모두 연습한다면 다음과 같이 구성할 수 있습니다. 빌드 도구와 세부 디렉터리 구성은 각자 선택합니다.

```text
내 fork/
├── gof/                         # 공용 실습 목표
├── java/                        # 개인 Java 풀이
│   └── ...
└── kotlin/                      # 개인 Kotlin 풀이
    └── ...
```

공용 목표를 개선하고 싶다면 변경 사항을 원본 저장소에 pull request로 제안할 수 있습니다. 개인 풀이를 공용 저장소에 제출할지는 스터디 운영 방식에 따라 정합니다.
